Cold-chain transport logger

An STM32 logger that watches temperature and knocks during transport and raises an alarm when either goes out of range. A pair project for Embedded Processors at UESTC.

Team
Pair project with Elyas Omar
Board
NUCLEO-L432KC (STM32L432KC, Arm Cortex-M4F)
Sensors
TMP102 temperature (I2C), ADXL345 accelerometer (SPI)
Tools
C++, Mbed OS 6, Keil Studio
Module mark
Embedded Processors: 82%

How it works

Medicines and vaccines have to stay within a temperature range in transit, and a dropped box can damage them too. The logger sits idle until a button press starts a journey. It then reads both sensors every two seconds, sleeping in between, and logs every event. If the temperature leaves its range or the accelerometer sees a shock, it switches to an alert state: the red LED comes on and a 2 kHz tone beeps. Three good temperature readings in a row return it to normal, and a second button press ends the journey and prints the full event log over serial.

The design follows the WHO's 2 to 8 °C cold-chain range for vaccines and a 2 g shock limit. The build we submitted has its limits set to 20 to 30 °C and 1.2 g.

A fault worth remembering

Partway through, both sensors stopped responding at once. I tested each one on its own, which pointed to the board rather than our code: on the NUCLEO-L432KC, solder bridges SB16 and SB18 join two of the pins we were using for SPI to the I2C pins. Moving the SPI bus to free pins fixed it.

Code structure

The code is split into modules, each with its own header: the main state machine, a driver for each sensor, and the event log. The button only sets a flag inside its interrupt, and the main loop does the work, because printing and sleeping aren't safe inside an interrupt handler.
